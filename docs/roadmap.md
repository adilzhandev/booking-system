# План разработки

Работаем небольшими этапами. Для каждого: объяснение и причина выбора,
структура файлов, код только этого этапа, разбор, типичные ошибки и задание.
Статус «готово» относится к артефактам этапа, а не ко всему API.

| № | Этап | Результат | Статус |
|---|---|---|---|
| 1 | Requirements | Требования, user stories, acceptance criteria, API-контракт | Готово |
| 2 | Database design | ERD, SQL-миграции, индексы и проект решения гонок | Готово; SQL проверен на PostgreSQL |
| 3 | Project initialization | Java 21, Spring Boot, Maven Wrapper, зависимости, конфигурация | Запланировано |
| 4 | Entities | User/Room/Booking, enum, auditing | Запланировано |
| 5 | Repositories | Запросы, pagination, метод блокировки Room | Запланировано |
| 6 | DTO | Request/response, validation, ручные mapper | Запланировано |
| 7 | Services | Комнаты, чтение, границы транзакций; без готовой логики брони | Запланировано |
| 8 | Exception handling | Общий error DTO и RestControllerAdvice | Запланировано |
| 9 | Authentication / JWT | BCrypt, register/login, JWT, SecurityFilterChain | Запланировано |
| 10 | Booking logic | Создание, чтение, отмена и доступность | Запланировано |
| 11 | Concurrency protection | Подключение locking и преобразования ошибок constraint в сервисе | Запланировано |
| 12 | Tests | Unit + Testcontainers + конкурирующие HTTP-запросы | Запланировано |
| 13 | Docker | Dockerfile, Compose, окружение, проверка запуска | Запланировано |
| 14 | Swagger | OpenAPI и проверка через браузер | Запланировано |
| 15 | README | Финальная документация проверенного приложения и примеров | Запланировано |

Ограничение пересечений входит в схему уже на этапе 2. Этап 11 объяснит
транзакционные границы, JPA flush, блокировки и HTTP-ошибки на работающем коде.
README создаём с самого начала и обновляем вместе с фактическим прогрессом.
Не добавляем коммиты за несуществующую работу и не меняем даты коммитов.
