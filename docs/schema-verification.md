# Проверка схемы — этап 2

Дата: 2026-09-27. Среда: PostgreSQL 18.6, отдельный временный кластер с Unix
socket, без TCP listener. Существующие базы не использовались. После проверки
кластер остановлен. V1–V4 выполнены по порядку через psql, каждая в транзакции.

Это проверка SQL-схемы. Flyway runtime, JPA, HTTP, JWT, Docker Compose и
Testcontainers ещё не созданы/не проверены. Тесты приложения появятся на этапе 12.

wait_event_type='Lock'. Это проверяет конфликт незавершённых транзакций,
а не два последовательных запроса. Проверка выполнялась без Room FOR UPDATE,
чтобы отдельно доказать гарантию exclusion constraint.

## Как повторить гонку вручную

Используй **одноразовую пустую учебную БД** с применёнными V1–V4.
Фикстуры ниже имеют заведомо ненастоящий password и не предназначены для login.

```sql
INSERT INTO users (id, email, password, first_name, last_name)
VALUES
  (900001, 'race-a@example.com', 'not-a-login-hash', 'Race', 'A'),
  (900002, 'race-b@example.com', 'not-a-login-hash', 'Race', 'B');

INSERT INTO rooms (id, name, capacity)
VALUES (900001, 'Concurrency lab', 4);
```

В первом psql-сеансе выполни и пока оставь транзакцию открытой:

```sql
BEGIN;
INSERT INTO bookings (user_id, room_id, start_time, end_time)
VALUES (900001, 900001, '2030-01-10 10:00:00+05', '2030-01-10 11:00:00+05');
```

Во втором psql-сеансе той же БД:

```sql
\set VERBOSITY verbose
BEGIN;
INSERT INTO bookings (user_id, room_id, start_time, end_time)
VALUES (900002, 900001, '2030-01-10 10:00:00+05', '2030-01-10 11:00:00+05');
```

Второй INSERT ждёт. Вернись в первый сеанс и выполни `COMMIT;`.
Во втором появится ошибка 23P01 с именем ex_bookings_room_active_period.
Выполни во втором `ROLLBACK;`, затем проверь:

```sql
SELECT count(*)
FROM bookings
WHERE room_id = 900001 AND status = 'ACTIVE';
-- Ожидается 1.
```

Не делай COMMIT первого сеанса до запуска второго INSERT: тогда проверишь
только последовательный конфликт. Дополнительное упражнение: повтори с другим
свободным интервалом, но откати первую транзакцию; вторая должна получить
возможность завершиться. Этот дополнительный сценарий пока не входит в
зафиксированный выше автоматизированный прогон.
